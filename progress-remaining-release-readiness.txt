## Learnings from the Prior Ralph Loop

These lessons were learned during US-RR-001 through US-RR-012 and must inform future Ralph iterations.

**1. PRD checkbox updates can drift from progress.txt.**
The original PRD.md required two reconciliation passes because story completion was recorded in
`progress.txt` before PRD checkboxes were consistently updated. The root cause was a label-casing
bug that prevented checkbox ticking in early iterations. The lesson: the commit containing the
implementation must also contain the PRD checkbox update. The Ralph execution rule at the top of the
PRD enforces this — enforce it strictly.

**2. progress.txt is evidence, not the source of truth.**
When `progress.txt` says a story is complete but PRD checkboxes are unchecked, the rule is: verify
both. Check the actual files and git commits. If the code and tests satisfy all acceptance criteria,
the story is complete regardless of checkbox state. If the code does not satisfy all criteria, the
story is not complete regardless of what `progress.txt` says.

**3. Future PRDs must avoid deferred unchecked criteria in earlier stories.**
The original PRD had a criterion in US-RR-004 that said "remove xfail mark after US-RR-011 is
implemented." This caused Ralph to re-select US-RR-004 as incomplete. The fix: deferred criteria
belong in the story that owns them, not in an earlier story. US-RR-004's xfail removal criterion was
moved to US-RR-011 where it was properly completed.

**4. Story completion should be proven by commits, tests, and file inspection — not by self-report.**
The cleaning of this PRD required verifying each story against current file content and git history.
Progress notes that say "completed" without a commit hash or file evidence are insufficient. Every
Ralph iteration summary must include: commit hash, files changed, commands run, and validation result.

**5. grep criteria need to be scoped to source files.**
`grep -r "rex-insecure-default-secret" .` matches `PRD.md` and `progress.txt` where the string
appears as documentation. Future criteria must scope grep to `--include="*.py"` or similar to avoid
false positives from documentation files.

**6. `pytest --collect-only -q 2>&1 | grep -i "error"` is unreliable.**
It returns test function names containing the word "error" (e.g., `test_handle_error`). Use
`grep -E "(ERROR|ImportError|ModuleNotFoundError)"` or check the summary line with `tail -5`.

**7. `python -m pip_audit` not `pip-audit`.**
The `pip-audit` CLI alias was not in PATH in the project's Python environment. Use `python -m pip_audit` in all commands.

**8. `bridge/` modules use bare import names.**
`pythonpath = [".", "bridge"]` in `[tool.pytest.ini_options]` is the correct least-invasive fix for
bare imports of bridge modules in tests.
