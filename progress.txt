- Renamed `_get_jwt_secret()` → `get_jwt_secret()` (now public, added to `__all__`)

- Updated internal callers in `authenticate()` and `get_current_user()`
- Added `TestGetJWTSecret` class in `tests/test_us047_user_auth.py` with 2 new tests (negative + positive)
- Added `REX_JWT_SECRET` to `.env.example` in new "JWT Authentication" section with generation command

Files changed:
- `rex/auth.py` (removed fallback, renamed function, updated callers, updated `__all__`)
- `tests/test_us047_user_auth.py` (added `TestGetJWTSecret` class)
- `.env.example` (added `REX_JWT_SECRET` section)

Learnings for future iterations:
- Existing `tmp_data_dir` fixture already sets `REX_JWT_SECRET=test-secret-key` so all pre-existing tests continued to pass without modification
- `grep` on full repo runs slowly on Windows — use the `Grep` tool scoped to specific dirs for fast checks
- The 2 failures in `pytest tests/ -k "jwt or auth"` are pre-existing `flask_proxy` missing-module failures (KNOWN_FAILURES.md category)

- `pip-audit` is not in PATH; use `python -m pip_audit` instead.
- Story status checkboxes are in progress.txt (Story Status section), NOT in PRD.md.
- PRD.md uses `### US-RR-NNN:` section headers for stories (no checkboxes in PRD).
- BASELINE.md is a working note file (not committed) created in repo root for US-RR-001.
- `bridge/` modules are imported as bare module names (e.g., `import rex_calendar_bridge`). Adding `pythonpath = [".", "bridge"]` to `[tool.pytest.ini_options]` in `pyproject.toml` is the correct least-invasive fix.

## Iteration 4 - US-RR-004: Invert Twilio fail-open test

- Renamed `test_validate_signature_returns_true_when_twilio_missing` → `test_validate_signature_returns_false_when_twilio_missing`
- Changed assertion from `assert result is True` to `assert result is False`
- Added docstring explaining fail-closed contract
- Marked test `@pytest.mark.xfail(strict=True)` referencing US-RR-011 (implementation fix not yet landed)
- 14 passed, 1 xfailed — CI green

Files changed:
- `tests/test_ph001_twilio_handler.py` (test renamed, assertion inverted, xfail added)
- `progress.txt` (US-RR-004 marked [x], iteration notes added)

Learnings for future iterations:
- `_validate_twilio_signature` does lazy `from twilio.request_validator import ...` inside the function body, so `patch.dict("sys.modules", {"twilio": None, ...})` correctly triggers the ImportError branch at call time even when the module is already cached.
- `xfail(strict=True)` is the right marker here: test expects False but current impl returns True (fail-open), so it xfails now and will need the mark removed after US-RR-011 changes the impl to return False.
