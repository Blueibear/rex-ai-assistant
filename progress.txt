## Iteration 12 - US-RR-012: Add Twilio signature validation to voicemail route

- Added `_require_signature(auth_token)` guard to `inbound_voicemail` route — unsigned requests now receive HTTP 403
- Route previously accepted any POST to `/telephony/inbound/voicemail` without verifying the Twilio signature, allowing forged voicemail callbacks to inject arbitrary content
- After fix, all 4 Twilio routes (`inbound_call`, `inbound_gather`, `inbound_voicemail`, `inbound_sms`) enforce signature validation identically
- Added `test_inbound_voicemail_rejects_bad_signature` — confirms 403 when `_validate_twilio_signature` returns False
- Added `test_inbound_voicemail_saves_with_valid_signature` — confirms 200 and `_save_voicemail` called with correct args when signature is valid
- All 17 tests in `test_ph001_twilio_handler.py` pass

Files changed:
- `rex/telephony/twilio_handler.py` (added `_, auth_token, _ = creds` + `_require_signature` call to `inbound_voicemail`)
- `tests/test_ph001_twilio_handler.py` (added 2 voicemail signature tests)

Route audit — all Twilio routes now signed:
- `inbound_call` — `_require_signature` present (pre-existing)
- `inbound_gather` — `_require_signature` present (pre-existing)
- `inbound_voicemail` — `_require_signature` added (this story)
- `inbound_sms` — `_require_signature` present (pre-existing)

Learnings for future iterations:
- The voicemail route is called both as a direct action (user records) and as an async transcription callback — both paths are Twilio-originated so signature validation applies to both
- Pattern for adding the guard: unpack `_, auth_token, _ = creds` then call `_require_signature(auth_token)` before any form data access

## Iteration 11 - US-RR-011: Twilio signature validation fail closed when package missing

- Changed `_validate_twilio_signature` `ImportError` branch from `return True` (fail-open) to `return False` (fail-closed)
- Updated warning message to: "Twilio package not installed — rejecting request as unsigned."
- Updated docstring to document the fail-closed contract and the rationale
- Removed `@pytest.mark.xfail` from `test_validate_signature_returns_false_when_twilio_missing` in `tests/test_ph001_twilio_handler.py`
- All 15 tests in `test_ph001_twilio_handler.py` pass; `grep -n "return True"` shows no path returning True without a real `validator.validate()` call

Files changed:
- `rex/telephony/twilio_handler.py` (ImportError branch: `return True` → `return False`; updated docstring and warning message)
- `tests/test_ph001_twilio_handler.py` (removed `xfail` marker from `test_validate_signature_returns_false_when_twilio_missing`)

Learnings for future iterations:
- The `except ImportError: return True` pattern is a classic fail-open bug — always grep for it in security reviews of optional-dependency integrations
- `patch.dict("sys.modules", {"twilio": None, "twilio.request_validator": None})` correctly forces the ImportError branch even when twilio is installed in the test environment

## Iteration 7 - US-RR-007: Protect /setup and /register routes

- Added `secrets.token_urlsafe(32)` setup token generated at `_create_flask_app()` time; stored in `app.config["SETUP_TOKEN"]`
- Added `_require_setup_token()` module-level helper (mirrors `_require_auth()` style) using `current_app.config`
- `POST /api/setup/complete`: requires `X-Setup-Token` header; token consumed (set to None) on first success; subsequent calls return 403
- `POST /api/auth/register`: requires `X-Setup-Token` when `user_count == 0` (pre-setup race protection); no change when users already exist
- Created `tests/test_rr007_setup_register_protection.py` with 9 security tests (all pass)
- Updated 11 existing test files to pass the setup token when registering the first user
- `test_duplicate_setup_returns_409` renamed to `test_second_setup_attempt_returns_403` (token consumed → 403 not 409)
- 147 tests passing for `-k "setup or register"`, 132 for directly modified test files

Files changed:
- `rex/gui_app.py` (added `import secrets`, `_require_setup_token()`, `app.config["SETUP_TOKEN"]`, updated `_setup_complete` and `_auth_register`)
- `tests/test_rr007_setup_register_protection.py` (new — 9 security tests)
- `tests/test_us058_setup_wizard.py` (updated all setup calls with token; renamed duplicate test)
- `tests/test_us047_user_auth.py` (updated all first-user register calls)
- `tests/test_us048_data_isolation.py` (updated `_register_and_login` and direct first-user calls)
- `tests/test_us049_avatar.py`, `test_us051_personality_ui.py`, `test_us052_permissions.py`, `test_us059_ha_setup.py`, `test_us060_devices.py`, `test_us061_command_history.py`, `test_us063_quick_actions.py`, `test_chat_api.py` (updated `_register_and_login` / first-user register)

Learnings for future iterations:
- `_require_setup_token()` uses `current_app.config` (Flask thread-local) just like `_require_auth()` uses `request` — consistent pattern
- Token check must be BEFORE field validation so attackers cannot probe validation errors without the token
- Second-user registrations (user_count > 0) need NO token — only the first user is vulnerable to the race attack
- `client.application.config.get("SETUP_TOKEN")` is how Flask test clients read app config in tests
- Ruff auto-fixed one unused import in a test file; Black reformatted `test_us047_user_auth.py`
